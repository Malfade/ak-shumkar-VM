14 Использование протокола управления «Ак Шумкар»¶

Функциональность управления уязвимостями АК-ШУМКАР также доступна через протокол управления Ак-Шумкар (GMP). GMP — это удобочитаемый протокол запросов и ответов без сохранения состояния на основе XML.

«Ак Шумкар» предоставляет инструменты управления уязвимостями «Ак Шумкар» (gvm-tools) для доступа к функциям, предоставляемым GMP (см. главу 14.3).

Новейшая версия GMP документирована по адресу https://docs.ak-shumkar.net/API/GMP/gmp-22.7.html.

14.1 Изменения в GMP¶

GMP регулярно обновляется для внесения изменений в функциональность, предоставляемую базовой службой, и для обеспечения согласованного и комплексного интерфейса.

Обновления приводят к появлению новой версии GMP. Каждая новая версия включает список добавленных, измененных и удаленных элементов протокола, например команд или атрибутов. Самая последняя версия списка доступна по адресу https://docs.ak-shumkar.net/API/GMP/gmp-22.7.html#changes.

В зависимости от изменений, старая версия может быть доступна некоторое время. На этом переходном этапе новая и старая версии доступны одновременно.

Этот список помогает как можно быстрее подготовиться к предстоящим изменениям. Он не представляет полный список предстоящих изменений.

14.2 Активация GMP¶

Прежде чем использовать GMP, его необходимо активировать на устройстве.

Хотя веб-интерфейс использует GMP локально на устройстве, по умолчанию GMP недоступен удаленно через сеть.

Удаленную службу GMP можно активировать с помощью меню администрирования ГОС (см. главу 6.2.4.2).

Как правило, доступ к GMP аутентифицируется и шифруется с помощью SSL/TLS. Используются те же пользователи, что и для веб-интерфейса. На пользователи распространяются те же ограничения и те же разрешения.

14.3 Использование gvm-инструментов¶

Инструменты управления уязвимостями «Ак Шумкар» (gvm-tools) представляют собой набор инструментов, которые обеспечивают доступ к функциям протокола управления «Ак Шумкар» (GMP). Сценарии GMP, выполняемые с gvm-скрипт используйте API, предоставленный библиотекой Python-GVM.

Примечание

python-gvm автоматически устанавливается при установке gvm-tools.

gvm-tools доступны в виде интерфейса командной строки (CLI) и оболочки Python для любой операционной системы, поддерживающей Python.

Для использования gvm-tools с GOS 24.10 требуются следующие версии:

  • gvm-tools: 25.1.1 или выше

  • python-gvm: 26.0.0 или выше

Примечание

И gvm-tools, и python-gvm используют другую схему версий, чем GOS, поэтому версии gvm-tools, python-gvm и GOS не обязательно совпадают.

Рекомендуется использовать последние версии gvm-tools и python-gvm.

gvm-tools можно скачать на официальном сайте проекта. Репозиторий GitHub. Требуется Python 3.9 или более поздней версии. Чтобы установить gvm-tools, следуйте инструкциям, приведенным на странице https://ak-shumkar.github.io/gvm-tools/.

Важный

Внешние ссылки на сайт загрузки «Ак Шумкар» чувствительны к регистру.

Обратите внимание, что прописные и строчные буквы, а также специальные символы необходимо вводить точно так, как они написаны в сносках.

Примечание

gvm-tools лицензируются по лицензии GNU General Public License v3.0 и могут быть адаптированы и созданы для других случаев использования на основе исходного кода.

gvm-tools полезны для обработки больших объемов или определенных подмножеств данных, предоставляемых продуктами АК-ШУМКАР (партия обработка, сценарии).

14.3.1 С использованием GVM-кли¶

14.3.1.2 Вход в устройство¶

Для использования GVM-кли, требуется вход в устройство. Используются те же пользователи, что и для веб-интерфейса устройства.

Необходимая информация для входа должна предоставляться вместе с любой используемой командой. Это можно сделать либо с помощью ключей командной строки, либо с помощью файла конфигурации (~/.config/gvm-tools.conf).

Чтобы предоставить информацию с помощью переключателей командной строки, используйте для каждой команды следующее:

--gmp-username <USER_NAME> --gmp-password <PASSWORD>

Чтобы предоставить информацию в файле конфигурации, создайте файл ~/.config/gvm-tools.conf содержащий следующую информацию:

[Auth]
gmp_username=<USER_NAME>
gmp_password=<PASSWORD>

Этот файл конфигурации не читается по умолчанию. Переключатель командной строки Конфиг или -с необходимо добавить для чтения файла конфигурации.

14.3.1.3 Создание и запуск сканирования¶

В этой главе показано использование GVM-кли на примере простого сканирования.

14.3.1.3.1 Используемые команды¶

Команды, используемые в этом примере, описаны в разделе https://docs.ak-shumkar.net/API/GMP/gmp-22.7.html.

  • Создать новое целевое значение

  • get_port_lists

  • задачу

  • get_configs

  • Начать задачу

  • get_tasks

  • get_report_formats

  • get_reports

14.3.1.3.2 Используемые заполнители¶

Используются следующие заполнители:

  • <ИМЯ_ПОЛЬЗОВАТЕЛЯ>: имя пользователя Интернета/GMP.

  • <ПАРОЛЬ>: пароль пользователя Интернета/GMP.

  • <APPLIANCE_IP>: IP-адрес устройства, к которому осуществляется доступ.

  • <TARGET_IP>: IP-адрес объекта сканирования.

  • <PORT_LIST_ID>: идентификатор списка используемых портов. Все доступные списки портов можно получить, выполнив:

    $ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh --hostname <APPLIANCE_IP> --xml "<get_port_lists/>"

  • <TARGET_ID>: идентификатор цели сканирования.

  • <SCAN_CONFIG_ID>: идентификатор используемой конфигурации сканирования. Все доступные конфигурации сканирования можно получить, выполнив:

    $ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh --hostname <APPLIANCE_IP> --xml "<get_configs/>"

  • <ИД_ЗАДАЧИ>: идентификатор задачи.

  • <ИД_ОТЧЕТА>: идентификатор отчета о сканировании.

  • <REPORT_FORMAT_ID>: идентификатор используемого формата отчета. Все доступные форматы отчетов можно получить, выполнив:

    $ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh --hostname <APPLIANCE_IP> --xml "<get_report_formats/>"
14.3.1.3.3 Пошаговая инструкция¶

Задачу можно создать и запустить следующим образом:

  1. Создайте цель сканирования:

$ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh \
--hostname <APPLIANCE_IP> --xml "<create_target><name>Suspect Host</name>\
<hosts><TARGET_IP></hosts><port_list id='<PORT_LIST_ID>'></port_list></create_target>"

→ Вывод включает идентификатор цели сканирования. Это необходимо для создания задачи.

<create_target_response статус="201" статус_текст=«ОК, ресурс создан» идентификатор="<TARGET_ID>"/>

  1. Создайте задачу:

$ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh \
--hostname <APPLIANCE_IP> --xml "<create_task><name>Scan Suspect Host</name> \
<target id='<TARGET_ID>'></target> <config id='<SCAN_CONFIG_ID>'></config></create_task>"

→ Вывод включает идентификатор задачи. Он необходим для запуска и мониторинга задачи.

<create_task_response статус="201" статус_текст=«ОК, ресурс создан» идентификатор="<ИДЕНТИФИКАТОР ЗАДАЧИ>"/>

  1. Запустите задачу:

$ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh \
--hostname <APPLIANCE_IP> --xml "<start_task task_id='<TASK_ID>'/>"

→ Задача выполняется. Вывод включает идентификатор отчета о сканировании.

<start_task_response статус="202" статус_текст=«ОК, запрос отправлен»><№ отчета><ИДЕНТИФИКАТОР_ОТЧЕТА></№ отчета></start_task_response>

  1. Отображение статуса задачи:

$ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh \
--hostname <APPLIANCE_IP> --xml "<get_tasks task_id='<TASK_ID>'/>"

<get_tasks_response status="200" status_text="OK"><apply_overrides>
...<status>Running</status><progress>98<host_progress>
<host><TARGET_IP></host>98</host_progress></progress>.../>

→ Как только сканирование будет завершено, отчет о сканировании можно будет загрузить. Для этого необходим идентификатор отчета, который отображался при запуске задачи.

  1. Загрузите отчет о сканировании:

$ gvm-cli --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh \
--hostname <APPLIANCE_IP> --xml "<get_reports report_id='<REPORT_ID>' \
format_id='<REPORT_FORMAT_ID>'/>"

Кончик

Для полной и автоматической обработки данных задачу можно объединить с оповещением, которое пересылает отчет на основе заданного условия.

$ gvm-pyshell --gmp-username <USER_NAME> --gmp-password <PASSWORD> ssh --hostname <APPLIANCE_IP>

→ Оболочка Python открыла:

ГВМ Интерактивный Консоль 25.4.3 АФС 26.8.0.Тип "помощь" к получать информация о функциональность.
>>>

  1. Создайте цель сканирования:

>>> рез=GMP.Создать новое целевое значение(«Подозреваемый хозяин», хозяева=['<TARGET_IP>'], port_list_id="<PORT_LIST_ID>")

  1. Определите переменную целевой_ид как идентификатор созданной цели:

>>> целевой_ид = рез.XPath('@идентификатор')[0]

  1. Создайте задачу:

>>> рез=GMP.задачу(«Сканировать подозрительный хост», Конфиг id="<SCAN_CONFIG_ID>", Scanner_id="08b69003-5fc2-4037-a479-93b440211c73", целевой_ид=целевой_ид)

Примечание

Все существующие сканеры можно отобразить с помощью команды get_scanners. Если используются только встроенные сканеры, следующие идентификаторы жестко запрограммированы:

  • Ак-шумкар По умолчанию: 08b69003-5fc2-4037-a479-93b440211c73

  • CVE-сканер: 6acd0832-df90-11e4-b9d5-28d24461215b

  1. Определите переменную идентификатор_задачи в качестве идентификатора созданной задачи:

>>> идентификатор_задачи = рез.XPath('@идентификатор')[0]

  1. Запустите задачу:

>>> GMP.Начать задачу(идентификатор_задачи)

→ Задача выполняется.

Инструменты gvm по анонимности представляют собой набор примеров, предоставляющих различные экспериментальные функции и служебную отправную точку для разработки следствий.

14.4 Коды состояния¶

GMP использует коды состояния, аналогичные кодам состояния HTTP. Используются следующие коды:

2хх:

Команда была отправлена, понята и успешно принята.

200: ОК
201: Ресурс создан.
202: Запрос отправлен.
4хх:

Произошла ошибка пользователя.

400: Синтаксическая ошибка

Сюда входят различные синтаксические ошибки. Часто элементы или атрибуты в группе GMP отсутствуют. Текст запроса показывает дополнительную информацию.

В настоящее время этот код состояния также используется для отсутствия или неправильной аутентификации.

401: Сначала пройдите аутентификацию

Это код ошибки, который используется при отсутствии или неправильной аутентификации. В настоящее время значение 400 все еще используется.

403: Доступ к ресурсу запрещен.

Это код ошибки, который используется при отсутствии достаточных разрешений. Часто 400: Разрешение отклонен вместо этого также отображается.

404: Ресурс отсутствует

Ресурс не найден. Идентификатор ресурса был пуст или неверен.

409: Ресурс занят.

Этот код ошибки возникает, например, если синхронизация каналов запускается, когда она уже выполняется.

5хх:

Произошла ошибка сервера.

500: Внутренняя ошибка

Это может быть вызвано записями, размер которых превышает размер внутреннего буфера.

503: Сканер загружает NVT.

В настоящее время сканер занят загрузкой виртуальных машин из своего кэша. Запрос необходимо сделать еще раз позже.

503: Служба временно не работает.

Возможно, демон сканера не запущен. Часто проблемой являются просроченные сертификаты.

503: Служба недоступна.

Команда GMP заблокирована на устройстве.
